The idea GitKraken is missing

Worktrees are places, not a footnote

GitKraken shows one WIP node for the checkout you opened and lists other worktrees in a side panel. With Claude running several sessions in parallel worktrees, the useful question is "what's in progress, where, and who's doing it?", so the graph should answer it.

A WIP node per worktree

Every dirty worktree gets its own ghost node at the top of the graph, joined by a dotted line to the commit it's built on. A clean worktree adds no row, only a ring on its HEAD commit.

The session comes with it

A worktree's card and WIP row show the Claude session working there (Running, Needs you, Idle) using the same pills as Roost. Click through to the session window or its Roost pane.

Commands run where the branch is checked out

Git won't check out a branch that's already checked out in another worktree. Perch runs each operation in the worktree that owns the branch (git -C), so you don't switch first. Double-clicking such a branch offers to open that worktree instead of failing.

Drag to start a worktree

Drop a branch or commit on New worktree to create ..\perch--branch with the existing WorktreeLayout naming. You can also tick a box to start a Claude session there.

GitKraken today

  • One WIP node, for the open repo tab only
  • Other worktrees listed in a side panel, away from the graph
  • Checking out a branch held by another worktree fails with git's error
  • No idea which agent or terminal is editing which tree

Perch Tree

  • Every dirty worktree has a WIP node, each tied to its own HEAD
  • Worktree cards sit at the top of the rail, and hovering one highlights its lane
  • Operations are sent to the worktree that owns the branch, and you see where before confirming
  • Live session state on every worktree, with a guard before git changes files under a working session
Interaction model

Gestures, where they run, and what guards them

Each drop opens a short menu instead of acting straight away, and the menu names the worktree and the git command first. This is the main difference from GitKraken, where a drop goes straight into a merge/rebase dialog.

Building on what's there

A phased path from today's View tree

Today's GitTreeWindow (branch-scoped node list, files, DiffView, staging, composer with the active-session guard) becomes the This branch scope of the same window. GitWorktreeScanner already reads worktrees with no git process, SessionWorktree already maps sessions to worktrees, PrStatusService can put PR badges on pills, and every spawn goes through GitRunner.

G1

Graph read model + canvas

A git log --topo-order --parents --decorate reader and a pure, unit-tested lane allocator in Core that keeps lanes stable across refreshes. An owner-drawn, row-virtualised GraphCanvas using the measure-or-paint pattern and OverlayDraw. Scope segment, ↑ ↓ Home Ctrl+G, click a rail branch to jump to it, paged history.

G2

Worktrees on the graph

A WIP node per dirty worktree, worktree cards with session state from SessionMonitor, hover to highlight a lane, live refresh from a watcher on the common dir's worktrees/*/HEAD and each index.

G3

Checkout

Double-click with worktree-aware handling, a stash/carry prompt for dirty trees, the active-session guard, and Undo from the reflog in the toast.

G4

Drag

Pointer-capture drag inside the canvas with a ghost and drop targets (branch, card, WIP, New worktree), and the drop menu. Merge, rebase, fast-forward and cherry-pick run in the owning worktree. A banner shows merge/rebase in progress with continue/abort and a conflict list.

G5

Remotes and PRs

Fetch, pull and push with ahead/behind counts, tracking branches, and PR/CI badges on pills from PrStatusService.

G6

Later

Interactive rebase (drag to reorder or squash), commit-to-session attribution, and dragging a branch onto a Roost pane.

Your call

Questions for you

Each question has a recommendation, so you can just reply "go with the recommendations" if they look right.

Q1 · Window

Grow View tree, or make a new window?

The mock is one window with a scope segment. The other option is a separate repo-level "Tree" with View tree left as it is.

Recommend: grow GitTreeWindow. Today's view becomes "This branch", so it's one window to maintain.
Q2 · Entry

How do you open it without a session?

View tree opens from a session row today. A repo-level graph also wants a tray entry, a perch tree [path] CLI, a Roost pane glyph and a recent-repos list.

Recommend: session row, Roost pane, and perch tree to start. A repo picker can come later.
Q3 · Dirty checkout

What happens to uncommitted changes when you check out?

GitKraken auto-stashes and pops. Options: auto-stash, always ask, or refuse.

Recommend: ask every time (stash / bring along / cancel), and remember the choice per repo if you want that.
Q4 · Sessions

How far should the session guard go?

If git rewrites files under a session that's working, the session can end up confused. Options: warn, block, or "Ask the session to do it", which sends Claude a prompt to rebase and resolve conflicts.

Recommend: warn plus the "Ask the session" option, and block only while it's Running mid-tool.
Q5 · Conflicts

Build a merge tool?

A three-way conflict editor is a big piece of work. The alternatives are opening your editor/IDE, or handing the conflict to a session.

Recommend: not in G4. Show a conflict list with "Open in editor" and "Ask Claude to resolve", and revisit after dogfooding.
Q6 · Interactive rebase

Drag commits to reorder or squash?

This is GitKraken's interactive rebase view. It's very satisfying to use and very easy to get wrong.

Recommend: G6, after the basic drags are proven, with reflog undo always visible.
Q7 · Worktree home

Where do new worktrees go?

Sibling ..\repo--branch (what WorktreeLayout already does), .worktrees/ inside the repo, or the bare .bare layout.

Recommend: sibling by default, as a per-repo setting.
Q8 · Remotes

Background fetch?

Ahead/behind counts are only as fresh as the last fetch. A timed fetch spawns git regularly, and on this machine EDR notices.

Recommend: fetch only when you click, plus once when the window opens. Off the UI thread, through GitRunner.
Q9 · Light/dark

Keep the per-window light toggle?

View tree has its own light mode (GitTreeLight). Lane colours would need light variants either way.

Recommend: keep it, and make lane hues theme roles with light/dark seeds.
Q10 · Attribution

Show which session made a commit?

The mock's "Made in" column matches commit hashes found in transcripts' git output. It's powerful, but scanning transcripts is expensive.

Recommend: G6. Index only new commits, and only for sessions Perch already tracks.
Risks

Challenges to plan for

High

Graph performance at scale

A ListBox with a template per row won't cope with 50k commits. The graph should be one owner-drawn canvas with virtualised rows, paging git log in chunks and caching lane state, following the overlay rule of allocating nothing in paint. For huge repos, check whether a commit-graph file exists.

High

Writing under a working session

Sessions run git too, so index.lock contention is real. Every write goes through one queue per repo, retries on lock contention with a visible message, and the session guard runs before anything rewrites the working tree.

Medium

Stable lanes

If lanes shuffle every time a session commits, it breaks your sense of where things are. The allocator has to be deterministic and prefer keeping existing lane assignments. That's pure Core code and easy to unit-test with fixtures.

Medium

Drag inside an owner-drawn surface

Avalonia's DragDrop works between controls. Inside the canvas we need our own pointer capture, hit-testing, ghost and auto-scroll near the edges. Dragging out to Roost (G6) would need real DragDrop with a custom format.

Medium

Destructive operations and undo

Rebase, reset and branch delete need reflog-backed Undo and plain confirmations. Force-push stays a deliberate menu item, never a drop result. Each operation also needs a GitRepoServiceIntegrationTests round-trip against a throwaway repo.

Medium

Watching many worktrees

One watcher per worktree index, plus the common dir, debounced through RepoWatchFilter. Many worktrees means many handles, so watch only while the window is open.

Medium

Lane colours as theme roles

About 8 lane hues that clear the 3:1 non-text contrast floor on both surfaces and stay distinct from the status colours (running green, awaiting yellow). They go through Theme, ThemeCodec.Roles and CvdSim, with PresetContrastTests coverage.

Medium

Verification gap

View tree's interactive parts have never been run live, and the headless renderer can't exercise pointer input. Drag and double-click need a manual test script (docs/git-graph-testing.md) and real dogfooding before they're called done.
