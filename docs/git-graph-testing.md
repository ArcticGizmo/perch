# Git graph: manual testing

Checks for the git graph work (`docs/git-graph-plan.md`), one section per checkpoint that changes something you can see or run. Each lists what to do, what you should see now, and what you'd have seen before.

## CP3: `perch bench-graph`

Measures the graph's read and layout on a real repository. Run it on the big repos you have checked out.

```
perch bench-graph <path-to-repo> [count]
```

`count` caps the full-history read (default 100,000). From a dev build: `src\Perch.App\bin\Debug\net10.0-windows10.0.19041.0\perch.exe bench-graph <repo>`. In PowerShell, pipe it (`| Out-String`) or redirect it (`> bench.txt`) if the output lands after the prompt.

**Expect** four sections:

1. **Open**: what the Tree window will pay on open: `scope`, then `git: refs, status, log` (run in parallel), `parse`, `layout`, `total`, then rows / lanes / worktrees (and how many are dirty) / refs.
2. **Refresh**: the same with lane hints from the open, and `0 commits changed lane` unless the repo changed between the two reads.
3. **Full history**: `git log`, MB of output, `parse`, `layout`, then commits, lanes, edges and the memory held, then `layout with hints`.
4. **Paging** (only past 2,000 commits): the cost of reading a page at three depths with `--skip`.

**Please send back** the output for each big repo. The budgets it's measured against are in the plan (open < 300 ms, layout < 150 ms per 100k commits, < 40 MB per 100k). If the paging lines grow with depth, CP3's follow-up is a streaming log read instead of `--skip`.

**Before:** `perch bench-graph` didn't exist (`perch --help` now lists it under Diagnostics).

## CP4–CP5: the graph in the Tree window

Open the Tree window as before: right-click a session row on the overlay → **View tree…**. Best tried in a repo with a few branches and at least one extra worktree (`git worktree add ..\<repo>--try <branch>`) with an uncommitted change in it.

1. **Graph instead of a list.** The left pane is titled **Graph · all branches** and shows every branch as coloured lanes with merge curves, ref pills right-aligned against the graph (the branch checked out in this window's worktree is a solid pill; branches checked out in any worktree carry a small folder mark; a small circle at the end means the remote branch is at the same commit), tags at the right of the subject, author and age. *Before:* a single-lane list of this branch's commits with a terminal base marker.
2. **WIP rows per worktree.** Each worktree with uncommitted changes has a row at the top ("N uncommitted changes", dashed node, a dashed pill with the worktree's folder name) and a dashed line down its own lane to the commit it's on. A clean worktree adds no row; its HEAD commit has a ring (thicker for this window's worktree). *Before:* only this worktree's WIP node.
3. **Opening lands where you are.** The window selects this worktree's WIP row if it's dirty (Changes / Staged groups and the composer appear as before), otherwise its HEAD commit.
4. **Selecting rows.** Click or ↑/↓/PgUp/PgDn/Home/End: a commit shows its files and diff, as before; this worktree's WIP row shows staging and the composer. Another worktree's WIP row shows "N uncommitted in <name>. Double-click to open that worktree here." **Double-click it** and the window re-points at that worktree (title changes; its WIP row now drives the staging panes).
5. **Scope segment** in the header: **All / Worktrees / This branch**. *Worktrees* shows only the main branch and what each worktree has checked out. *This branch* is the old view (the base picker "since ⑂ origin/main" appears only in this scope). The choice is remembered next time the window opens.
6. **Long history.** In a repo with more than 2,000 commits, scroll to the bottom: "Loading older commits…" shows and the next page appends without the lanes above moving.
7. **Live refresh.** With the window open, commit in another terminal (or have a session commit). Within a second the graph updates, the selection stays on the same commit (or WIP row), and the diff you were reading doesn't jump.
8. **Light/dark** (☀/☾ in the header) recolours the graph with its own lane palette.

Report anything that looks off with a screenshot. These checks have only been verified through the headless renderer (`git_graph_*.png`, `git_tree_*.png`), not on a real desktop.

## CP11: double-click to check out

Use a throwaway clone or a branch you don't mind moving, with at least one extra worktree (`git worktree add ..\<repo>--try <branch>`). Every successful checkout shows a toast at the bottom of the graph ("Checked out X", the git command underneath in mono, **Undo**, ✕); it hides after ~6 s unless the pointer is on it. Failures show git's own line in red for ~10 s, with no Undo. *Before (all of these):* double-clicking a pill, branch or commit did nothing; only another worktree's WIP row reacted.

1. **Clean tree, free branch.** With no uncommitted changes, double-click a local branch pill (or the branch in the rail's **Local** list). It checks out straight away, the solid pill and the ring move to it, and the window lands on its HEAD. Click **Undo**: back on the previous branch, toast "Back on <branch>".
2. **Double-click a commit row** (not on a pill). A commit with a local branch checks that branch out. A commit with only a remote branch creates a tracking branch ("Checked out x (tracking origin/x)"). A commit with neither opens a menu: "No branch points at abc1234" / **Check out abc1234 here, detached** / **Create a branch at abc1234…**.
3. **Create a branch.** From that menu pick **Create a branch at…**: a bar opens under the graph title ("New branch at abc1234", a name box, **Create and check out**, ✕). Type a name, Enter: the branch is created there and checked out. Esc closes the bar without doing anything. A bad name (e.g. with a space) shows git's error in the toast.
4. **Tag.** Double-click a tag in the rail's **Tags** list: the menu says "<tag> is a tag" and offers the detached checkout or a branch there.
5. **Remote branch.** Double-click a remote pill/rail row with no local branch of that name: a local tracking branch is created and checked out. If a local of that name exists, it's that local branch that gets checked out.
6. **Branch held by another worktree.** Double-click the branch your extra worktree has checked out: a menu says it's checked out in `<name>` and offers **Open <name> in this window** (the window re-points there) or **Check out abc1234 here, detached**.
7. **Dirty tree.** Make an uncommitted change (and an untracked file) and double-click another branch: a menu says "<worktree> has N changes not committed" and offers **Stash the N changes, then check out X**, **Bring the N changes to X**, **Cancel**.
   - *Stash:* the tree goes clean, a "Perch: before checking out X" stash appears in the rail's **Stashes**, toast "…; N changes stashed". **Undo** switches back *and* pops that exact stash (even if you stashed something else in between): your edits and the untracked file are back.
   - *Bring along:* the edits come with you (toast "…, changes brought along"); **Undo** carries them back.
   - If git refuses (e.g. a branch held elsewhere), a stash made for it is popped straight back: nothing is lost and no stash is left behind.
8. **Session guard.** With a Claude session running in this worktree, any checkout first shows a menu whose top line warns "A Claude session is working in this worktree…" with **Check out X anyway** / **Cancel** (or the stash/bring-along choices when dirty). It warns; it never blocks.
9. **Already there.** Double-click the branch this worktree is on: toast "<worktree> is already on <branch>." Nothing runs.
10. **Light/dark** recolours the toast and the branch bar.

## Feedback round 1: diff over the graph, steady header, resizable columns

1. **Diff over the graph.** The window is now graph (left) | files (right). Click a commit: its files fill the right pane, and the graph stays visible. Click a file (or select it and press Enter): its diff covers the graph, with a bar on top ("abc1234 · path", or "Working tree / Staged · path") and **✕** top right. ✕ or Esc goes back to the graph. While the diff is open, clicking other files switches the diff. The + / − stage buttons on file rows don't open it. "View diff" from a session opens straight onto that file's diff. *Before:* a third pane on the right always showed the diff, squeezing the graph.
2. **Steady header.** The All / Worktrees / This branch switch (and the "since ⑂ base" picker) now sit in the graph card's own title row, in a fixed place. The window header shows the branch, status and path, and trims instead of pushing anything (the path keeps its folder name). *Before:* the switch moved left and right as the branch name and status changed length.
3. **Branch pills.** The branch this worktree has checked out always gets its pill, even when the name is long. Long names lose their middle (`dependabot/…site-1e1827e218`) and hovering a pill shows the full name. *Before:* a long checked-out branch's pill vanished into "+1", and names were cut at the end.
4. **Resizable columns.** Hover the edge between the pills and the lanes, or between the lanes and the commit messages: the cursor becomes ↔ and a line shows. Drag to resize. Double-click an edge to put it back. The widths are remembered next time.
5. Light/dark recolours the diff bar.

## Feedback round 2

1. **Opens where there's room.** Open the graph from the overlay row's right-click → **Git graph…** (now the first item of that group, above Work items; the window is titled "Git graph"). It opens on the overlay's monitor, in the space beside the overlay, never underneath it (docked or floating), and shrinks to fit that space. Only this Perch's own overlay is known; a second Perch's floating overlay isn't (a docked one is, since it reserves the screen edge).
2. **Remote marks.** A local branch's pill (and its rail row) shows: nothing = local only, no remote branch; **●** = same commit as its upstream; **↑2 ↓1** = ahead/behind its upstream; **⊘** = its upstream is configured but gone. Hover for it in words ("2 commits ahead of origin/x", "Local only: no remote branch", …).
3. **Find commits.** With the graph showing, **Ctrl+F** opens "Find commits" (Ctrl+G too). As you type, matching rows (message, author, hash prefix, branch or tag name) are washed amber and the first is selected; "3 / 14" counts them, Enter / Shift+Enter or ‹ › walk them. Nothing in what's loaded → "No match in the newest 2,000 commits" and **Search older history**, which loads older pages until something matches. With a diff open, Ctrl+F still finds in the diff.
4. **Right-click, not double-click.** Right-click a commit row: Check out <its branches>, Check out abc1234 (detached), Create a branch at…, Create a worktree at…, Copy commit hash / message. Double-clicking a commit row now does nothing (a commit detail view is planned there); double-clicking a branch pill still checks it out.
5. **Columns.** A header row (Branch / tag · Graph · Commit message · Author · When) sits above the rows, with a ‖ grip on each draggable edge.
6. **Busy cover.** Checking out (double-click a pill, or any drop / Undo) greys the graph with a "Checking out X…" card until the refreshed graph is on screen.
7. **Delete a local branch.** Right-click a local branch (pill or rail) → **Delete <branch>…**. A merged branch just goes; one with unmerged commits asks first. The toast's Undo brings it back at the same commit (its upstream setting isn't restored). Not offered for a branch a worktree has checked out.
8. **Create a worktree from a menu.** Right-click a branch → **Create a worktree for <branch>** (a free branch goes straight in; one held elsewhere asks for a new branch name); right-click a tag or commit → **Create a worktree at…** (asks for a name).
9. **WIP rows.** No pill on a WIP row any more. This worktree's row says "N uncommitted changes"; another worktree's says "N uncommitted changes in <its folder>".
10. **Collapse the files pane.** The **›** at the top right of Files collapses it to a thin strip; the strip's **‹** brings it back at its old width. Remembered.

## Feedback round 3: file menu, toolbar, menu overflow

Use a throwaway clone that has a remote you can push to (a fork, or a bare repo: `git clone --bare . ../sandbox.git` then `git remote add origin ../sandbox.git`).

1. **Right-click a file in Changes.** Menu: **Stage <file>**, **Discard changes to <file>…** (tracked files only), **Delete <file>…**, then **Open file**, **Show in Explorer**, **Copy path**. Discard asks, then puts the file back to its staged (or committed) content. Delete asks, then removes it from disk: a tracked file shows up under Staged as a deletion (`D`), ready to commit; an untracked file or folder is just gone. *Before:* no right-click menu; discarding was only the diff's per-file button.
2. **Right-click a file in Staged.** Menu: **Unstage <file>**, **Discard all changes to <file>…** (staged and unstaged together, back to the last commit), **Delete <file>…**. For a file that's new in this commit, the dialog says discarding deletes it. For a rename (`git mv a b`), discarding brings `a` back and removes `b`. A file that's already deleted on disk has no Delete, Open or Show in Explorer.
3. **The toolbar.** Right of All / Worktrees / This branch in the graph card: **Pull ▾ · Push · Branch · Stash · Pop**. Hover each one to see what it will run.
   - **Pull** pulls this worktree's branch. It reads **Pull ↓3** when the remote branch is 3 ahead, and is greyed out on a detached HEAD or a branch with no upstream. **▾** offers **Fetch all**, **Pull (fast-forward only)**, **Pull (merge if diverged)** and **Pull (rebase)**. The one you pick runs and becomes what the button does (a ✓ marks it, and the button reads **Fetch** in that mode). A pull that moved the branch has **Undo** in its toast, which resets back. A pull that stops on conflicts shows the orange in-progress banner. *Before:* no pull or fetch in the window.
   - **Push** reads **Push ↑2** when 2 ahead. On a branch with no upstream it publishes to `origin` and sets tracking (`git push -u origin <branch>`; hover says so). It never forces: a rejected push shows git's reason in a red toast.
   - **Branch** opens the "New branch from <branch>" bar. Type a name and press Enter: the branch is created at HEAD and checked out, your changes stay as they are, and Undo switches back.
   - **Stash** (only when there are changes) stashes everything, untracked files included, as "WIP on <branch>"; Undo pops it back. **Pop** (only when there's a stash; it reads **Pop (3)** when there are 3) applies the newest stash and drops it. If it conflicts with your changes, a red toast says so and the stash stays in the list.
   - A credential prompt can't hang the window: if git would need to ask for a password in a terminal, the push or pull fails with git's message. A credential manager's own sign-in window still appears.
4. **Long branch names in menus.** Double-click a pill with a long name (a Dependabot branch) while this worktree has changes. The "Stash the 1 change, then check out …" and "Bring the 1 change to …" items wrap onto a second line inside the menu instead of running past its edge. The same goes for the session warning line, the drop menu and the right-click menus. *Before:* the text ran out past the menu's right edge.

## Feedback round 4: files pane clicks

1. **The heading toggles.** Click anywhere on the Files heading row (not only the **›**): the pane collapses to its strip. Click anywhere on the strip (not only the **‹**): it comes back at its old width. *Before:* only the chevrons did it.
2. **Empty space opens nothing.** With a few files in Changes (or a commit with a few files selected), click in the blank area below the last row. No diff opens. Clicking a row still opens its diff. *Before:* a click below the rows opened the diff of whichever file was selected, usually the first.

## Feedback round 5: toolbar groups, stashes in the graph

1. **Toolbar.** Separate rounded buttons, each with an icon: **Pull ▾ · Push**, a rule, **Branch**, a rule, **Stash · Pop**. Pull and its ▾ are one outlined control split by a short inset line. A button that can't run (Pull on a branch with no upstream, Stash with nothing to stash) is dimmed but still shows its tooltip saying why; clicking it does nothing. *Before:* one joined segment with a full-height edge between Pull and ▾.
2. **Stash from the WIP row.** Right-click the "N uncommitted changes" row → **Stash the N changes** (with a warning line if a Claude session is working there). On another worktree's WIP row it stashes that worktree's changes, next to **Open <worktree> in this window**. Undo pops it back.
3. **Stashes in the graph.** Every stash now has a row (placed by when it was made since round 9): a small box on its own dashed line down to the commit it was made on, a dashed `stash@{n}` pill, git's message ("On main: …" / "WIP on main: …") and its age. Click one: Files lists what it holds (untracked files too) and a file opens its diff. Right-click the row, its pill or its rail row → **Apply to <worktree>, keeping the stash**, **Pop into <worktree>**, **Drop stash@{n}…** (asks; the toast's Undo puts it back), **Copy message**. A stash made on a commit older than the loaded history has no row but is still in the rail. *Before:* only the newest stash existed anywhere (as "stash" in a collapsed rail section), with no row in the graph.
4. **Stashes in the rail.** The Stashes section is open by default and lists every entry by its message (trimmed at the end). Click one to jump to its row. **Pop (N)** on the toolbar counts all of them.
5. **Busy cover.** While git runs, the graph is greyed out much less (you can still read it behind the "Checking out…" card).

## Feedback round 6: branch dialog, stash rename, your lane, selection

Use a throwaway clone with a second worktree on its own branch (e.g. `git worktree add ../sandbox--example -b example`), and open the graph on that worktree.

1. **New branch is a dialog.** Click **Branch** on the toolbar: a "New branch" dialog opens over the middle of the window, with the window dimmed behind it. Type a name and press Enter (or click **Create and check out**): the branch is created at HEAD and checked out, and Undo switches back. Type `main` (or any branch that exists): "main already exists." shows in red under the box as you type and the button greys out. Try `has space`, `a..b` or `x.lock` for git's own rules. Esc, **Cancel** or a click on the dimmed area closes it and creates nothing. *Before:* a bar slid in at the top of the graph card.
2. **Branch at a commit, with changes.** With uncommitted changes, right-click a commit → **Create a branch at abc1234…**. The same dialog shows two choices under the name: **Stash the N changes first** (picked) and **Bring the N changes along**, plus an orange line if a Claude session is working here. Create runs with that choice; there's no second menu after it. The same dialog names a new worktree's branch (drag a commit onto **+ New worktree**: the button reads **Create worktree**). *Before:* the bar, then a stash / bring along menu.
3. **Rename a stash.** Right-click a stash row, its pill or its rail row → **Rename stash@{n}…**. The dialog starts with the stash's message, without git's "On main: " in front. Change it and press Enter: the row now reads "On main: <your text>", and the stash keeps its place (`stash@{1}` is still `stash@{1}`, and the others keep theirs). Undo in the toast puts the old message back. Rename stays greyed out until the text changes. *Before:* no rename.
4. **Your branch runs straight down the left.** The worktree's branch (`example`) is lane 0: its commits are a straight line down the far left, and `main` branches off it to the right, even when `main` has newer commits. Make a commit on `example`: it stays on the left line, and `main` doesn't take that line. Open the graph on the main worktree instead: now `main` is the straight line on the left. *Before:* `main` always held the left lane, so your own branch's new commits stepped out to the right.
5. **Your changes are the top row, and take the selection.** Select this worktree's HEAD commit (the one with the solid branch pill), then edit a file in the worktree. Within a moment the "1 uncommitted change" row appears as the **first** row, on the left lane straight above that commit, and it becomes the selected row (Files shows Changes). Its circle is at the left, not out past the stash lines. If another worktree is dirty too, its WIP row comes after yours. If a different commit is selected, or a diff is open, the selection stays where it was. *Before:* the WIP row was drawn in a lane to the right of the stashes, and the selection stayed on the commit.
6. **No row highlighted until you pick it.** Select a commit, or the WIP row: Files lists the files with none of them highlighted. Click one: it highlights and its diff opens. Close the diff (✕ or Esc): the highlight goes too. While a diff is open, moving through the list keeps working as before (staging a file with the diff open moves on to the next one). *Before:* the first file was always highlighted, so the rows didn't look clickable.
7. **New files say A.** Create an untracked file: it's listed under Changes as `A  newfile.md` in green, and stays `A` once staged. *Before:* it showed `?`. This was never an encoding problem: `?` is git's own code for an untracked file.
8. **Hand cursor on everything clickable.** Move the pointer over: a graph row and a branch pill (hand); the column edges in the graph's header (↔ resize arrows); the empty space below the last row (arrow). A file row in Files, every button (Refresh, Stage all, the toolbar, the toast's Undo, the in-progress banner's Continue/Abort, the diff's ✕, the dialog's Cancel), the radio choices in the new-branch dialog, and the items in a right-click menu all show the hand. A greyed-out button, a menu's italic note line and a dimmed toolbar button show the arrow; so do the scrollbars' arrow buttons, as elsewhere in Windows. *Before:* most buttons, the file rows, the menu items and the whole graph showed the arrow.
9. **Collapse Worktrees and Local.** In the rail, the **Worktrees** and **Local** headers now carry ▾ like Remotes, Tags and Stashes. Click either header: its cards or branches fold away to just the header (▸, with the count still showing); click again to bring them back. The **⋯** on Local still opens the hidden-branches menu without folding the section. Start a drag with Worktrees collapsed: the **+ New worktree** drop zone still appears under its header. Like the other sections, the state lasts while the window stays open and resets when it's opened fresh. *Before:* only Remotes, Tags and Stashes folded.
10. **Softer dark mode.** In dark mode (☀ in the header switches), the surfaces are neutral grey rather than blue-black, commit messages are a soft light grey rather than near-white, and lane colours are a little less saturated. Compare against `captures/2026-11-02-git-graph-dusk/before_after_dark.png`. Light mode is unchanged. *Before:* bright white subjects on a blue-black card.
11. **Author pictures on the nodes.** Open the graph on a GitHub repo where you're signed in to `gh`. Each commit's node is a circle with its author's GitHub picture, ringed in the lane colour; lanes sit a little further apart to make room. Merge commits keep their small dot. An author with no GitHub account (or before the lookup finishes, a second or two) shows their initials on a colour that stays the same for that person. Dependabot and anyone committing with a GitHub noreply email gets their picture without any lookup. The person button left of ☀ turns pictures off (plain dots, narrower lanes, no lookups) and on again; the choice is remembered. Close and reopen the window: pictures come straight from the cache (`%LocalAppData%\Perch\avatars`), with no new lookup for a week. Open a repo hosted somewhere other than GitHub: initials only, and no `gh` call. Sign out of `gh` (or rename it off PATH): initials only, and the graph works as before. Hover a node (picture, initials, or a plain dot with pictures off): a tooltip gives the author's name, email and when they authored it. Hovering a pill still gives the branch's full name. *Before:* plain dots, and no tooltip on a node.

## Feedback round 7: exact times, header-only column edges, Branch here, long names in menus

Use a throwaway clone that has (or gets) two branches with long names, e.g. `git branch dependabot/github_actions/actions-c673fd7efc` and `git branch dependabot/npm_and_yarn/site/site-1e1827e218` on different commits.

1. **Exact time on When.** Hover the "4d" (or "12 Oct 26") of any commit or stash row and hold still for half a second (sweeping across the column shows nothing): a tooltip gives the full date and time in your Windows region format, e.g. "Tuesday, 3 November 2026 2:15:07 PM" for English (Australia). Change the format in Windows Settings → Time & language → Region, then restart Perch: the tooltip follows it. The uncommitted-changes row ("now") has no tooltip. The node tooltip's "Authored …" line uses the same format. *Before:* no tooltip; the node tooltip used a fixed "Tue 3 Nov 2026, 14:15".
2. **Column edges only in the header.** Move the pointer down the Branch/tag | Graph edge (and the Graph | Commit message edge) over the commit rows: the cursor stays the hand, no line appears, and a press selects the row or picks up the pill as usual. In the header row the same spot shows ↔ and the line, drags to resize, and a double-click resets. *Before:* the ↔ edge ran the full height and took clicks meant for pills and nodes.
3. **Branch here… on a commit.** Right-click any commit row: **Branch here…** is the first item. The "New branch" dialog says "At abc1234 · <subject>.", with the choices **Just create it** (picked) and **Create it and check it out in <worktree>**. With uncommitted changes the second becomes two: **…stashing the N changes first** / **…bringing the N changes along**. **Just create it** + Enter: a new pill appears on that commit, nothing is checked out, files are untouched, and the toast reads "Created <name> at abc1234" with Undo (which deletes it). The checkout choices behave as **Create a branch at…** did. *Before:* only "Create a branch at abc1234…", lower in the menu, which always checked out.
4. **Branch here… on a pill and the WIP row.** Right-click a branch or tag pill (or its rail row): **Branch here…** is the second item, under Check out, and branches at that ref's commit ("At <branch name>."). Right-click this worktree's "N uncommitted changes" row: **Branch here…** opens the same dialog as the toolbar's **Branch** (new branch at HEAD, changes stay). Another worktree's WIP row doesn't offer it.
5. **Long names in the drop menu.** Drag one long branch's pill onto the other's. The menu lines cut each long name in the middle, as the pills do (`Merge dependabot/…s/actions-c673fd7efc into dependabot/…ite/site-1e1827e218 (checks out … in perch first)`), so the words around them stay readable. The git command under each line is shown **in full**, wrapping onto a second line rather than being cut. Hover an item: its tooltip gives the line with the full names. The drag ghost and its hint shorten the same way. Short names (`main`, `example`) are never cut. Compare `captures/20261103-141439-graph-feedback7-long/git_tree_drop_menu_long_1x.png`. *Before:* full names wrapped the line over three or four rows, and the command was cut from the left (`git swi…it merge …`).
6. **Long names in the right-click menu.** Right-click a long branch's pill: Check out / Create a worktree for / Hide / Delete name it with the middle cut, the same way.

## Feedback round 8: resizable rail, bulk hide

Use a throwaway clone with a few local branches (one checked out in an extra worktree) and some remote branches, a couple of which have no commit of yours (e.g. Dependabot's).

1. **Resizable rail.** Hover the line between the rail (Worktrees / Local / Remotes) and the graph: the cursor shows ↔. Drag it right: the rail widens and long branch names show more of their tail; the graph takes what's left. It stops at about 140 px narrow and 520 px wide. Close and reopen the window: the width is kept. Double-click the line: back to the default 210 px (and that's what reopens). Compare `captures/20261103-155015-rail-resize-hide-menu/git_tree_rail_wide_1x.png`. *Before:* the rail was a fixed 210 px.
2. **Hide all.** **⋯** on the Remotes header → **Hide all N remote branches**: every remote branch leaves the graph except `origin/main`, and the toast offers Undo (which brings them all back). The same on Local → **Hide all N local branches** skips `main` and any branch a worktree has checked out (N counts only what will go). With nothing left to hide, the item is greyed. *Before:* branches could only be hidden one at a time.
3. **Hide the ones that aren't mine.** **⋯** → **Hide remote (or local) branches that aren't mine**: a toast says it's looking for your commits, then "Hid N branches that aren't yours" with Undo. Branches with a commit of yours that `main` lacks stay. A branch you've just made with nothing on it yet has no commit of yours, so it goes too (Undo, or its eye, brings it back). With no git `user.email`/`user.name` set, nothing is hidden ("Every one of them is yours"). *Before:* only new remote branches could be hidden this way, via auto-hide.
4. **Show all, per section.** With branches hidden in both sections, Remotes' **⋯** offers **Show all N hidden remote branches** and Local's the local ones; each brings back only its own section. *Before:* one "Show all hidden branches" for both.
5. **The setting reads as a setting.** In Remotes' **⋯**, a divider separates the actions above from **Hide new remote branches that aren't mine**, which has a real checkbox (ticked when on). Clicking it flips the setting with a toast, as before. Local's **⋯** has no such checkbox (it's about remote branches). *Before:* the setting sat at the top of the menu with a ✓ text prefix, looking like one more action.

## Feedback round 12: picking several files

Use a throwaway clone. Make four changes: edit two tracked files (`a`, `b`), add a new file (`new.txt`), and delete a tracked file (`gone`) with `del`/`rm`, not git. Select the uncommitted-changes row so the Files pane shows Changes. Compare `captures/20261104-085900-files-multiselect/git_tree_files_multi_1x.png`.

1. **Pick with Ctrl/Shift.** Ctrl+click `a`, then Ctrl+click `new.txt`: both stay highlighted, and no diff opens (the diff shows whatever it did before). Shift+click picks a range; Ctrl+A picks them all; Ctrl+click a picked row un-picks it. A plain click goes back to one file and opens its diff, as before.
2. **The header button follows.** With 2+ files picked in Changes, **Stage all** reads **Stage (N)** and stages just those. Every row's **+** disappears while several are picked, and comes back when you're down to one. The same in Staged: **Unstage all** → **Unstage (N)**, and the **−** buttons go.
3. **Right-click a picked row** (with 2+ picked): **Stage N files**; then **Discard changes to N files…**, **Delete N files…**, **Stash N files**; then **Copy paths** (one per line).
   - **Discard** reverts the tracked files' unstaged changes (what's staged stays); it asks first. A new file has nothing to discard, so with `new.txt` picked it reads "Discard changes to 2 of the 3 files…", with a note pointing at Delete.
   - **Delete** removes the picked files from disk, skipping `gone` (it's already deleted): with `gone` picked it reads "Delete 2 of the 3 files…", with a note saying so. Tracked files become staged deletions. It asks first.
   - **Stash** makes one stash of only the picked files (staged and unstaged changes, new files included); everything else stays in the working tree. The toast offers Undo, which pops it back. It shows up in the graph and rail as "WIP on <branch>: N files".
   - In Staged, the menu says **Unstage N files**, and **Discard all changes to N files…** puts each back to the last commit (both sides), as the single-file version does.
4. **Right-click an unpicked row** while others are picked: the usual single-file menu for that row only.

## Feedback round 11: rail columns, tags, commit menu, busy toolbar

Use a clone with a second worktree, a branch that's behind or ahead of its upstream, one with no upstream, and plenty of tags (or this repo, which has 222). Compare `captures/20261104-082001-graph-feedback11/`.

1. **Local rows line up.** No coloured squares anywhere in the rail (Local, Remotes, Tags, Stashes). Local rows have three fixed columns: a lead mark on the left, the name, then ahead/behind on the right, then the eye slot. The branch checked out in this window has a ⌂; one checked out in another worktree has a small tree; others have an empty slot. Hover each for which worktree. The right column reads `↑2`, `↓3`, `↑1 ↓4`, `✓` when level with its upstream, and is blank when the branch has no upstream (or its upstream is gone). Its tooltip spells it out ("2 to push, 3 to pull (origin/x)"). The marks stay in one column whatever the name's length. A checked-out branch has no eye, but the column is still there. *Before:* coloured squares on the left, and a folder, ●/↑/↓/⊘ and the eye jumbled at the right edge at whatever position each row's marks happened to land.

Right-click a tag pill → **Hide <tag> from the graph**. The Tags header's **⋯** → **Hide all N tags** / **Show all N hidden tags** (Undo in the toast). *Before:* tags couldn't be hidden.

The menu has three groups, with dividers between them: **Check out <branch>** (for each branch there) and **Check out this commit (abc1234, detached)**; **Branch here…**, **Tag here…**, **Create a worktree at abc1234…**; **Copy commit SHA**, **Copy message**. **Tag here…** opens the name dialog ("New tag", checked as you type: a taken tag name or a bad one like `v1 final` says why). ## Feedback round 10: compact lanes

Use the repo from your screenshot (a few side branches near main, a stash, some hideable branches), or a throwaway clone with two branches off main that overlap in time.

1. **Hiding closes the gap.** Hide a branch whose line ran beside main (eye in the rail, or **⋯ → Hide all**). The branches that were further out move in a column; nothing is left with an empty column between it and main unless something still runs there. Show it again: it takes its column back and the others move out again. *Before:* after a hide, every line kept its old column, so the graph kept the hidden branch's empty gutter until the window was reopened.
2. **New lines start in the innermost free column.** A stash row, a fresh branch, or another worktree's uncommitted-changes row opens in the first column that's free at its row, usually the one next to main. *Before:* after any refresh, a new line opened out past every column the graph had ever used (the stash two or three columns out in your screenshot).
3. **Lines move only on a conflict.** A branch doesn't wander between columns along its length. When a new branch appears near the top (a fetch, a new commit on a fresh branch), the lines it runs beside move out a column, but only alongside it; lines that don't overlap it stay put.
4. **Same layout every time.** Close and reopen the window, or press Refresh: the graph looks the same as the live view did (it no longer depends on what was on screen before).
5. **Behind your upstream: the remote holds the main line.** In a clone, `git fetch` after someone else has pushed to `main`, without pulling (the rail shows `main` with `↓N`). `origin/main` is now the straight line down the left, and your local `main` pill sits further down that same line; nothing branches off to the side for origin's new commits. With uncommitted changes, their row is still the top row, one column out, with its dashed line down to your local `main`. Pull, and everything is one line again. *Before:* origin's new commits ran in their own column beside the line and joined it at your checkout.
6. **Diverged keeps your line.** Commit locally while still behind (`↑1 ↓N`): your branch takes the left line again and `origin/main`'s new commits branch off beside it, since you have work it doesn't. The same happens if the upstream is hidden or outside the scope (**This branch**).

## Feedback round 9: stashes in time order

Use a throwaway clone with a few commits a few minutes apart.

1. **An old stash sits among its history.** Make a change and stash it (`git stash push -m old`), then make and commit two more changes. Refresh: the stash row isn't at the top any more. It sits just above the commit it was made on, below the two newer commits, with a short dashed line down to its base. In this repo, `stash@{0}` "On main: cowork feasibility" (2 Oct) now sits between "Session recovery (#39)" and "Roost tabs (#38)": compare `captures/20261103-160122-stash-chronological/git_tree_stash_row_1x.png`. *Before:* every stash was stacked right under the uncommitted-changes rows, however old.
2. **Pop and stash again: back at the top.** Right-click that stash → **Pop into <worktree>**, then **Stash** from the toolbar. The new stash is made now, so its row is the first under the uncommitted-changes row(s), with a long dashed line down to the (older) commit it was made on.
3. **Stashes made on a commit in between.** Stash on an older checkout (`git switch --detach HEAD~1`, change a file, stash, `git switch -`). Its row sits above the newest commit that's older than the stash. It's never below the commit it was made on, even if that commit's time is newer than the stash (a rebase or a skewed clock).
4. **Several at the same spot.** Two stashes made between the same two commits: the newer one is higher.
5. **A stash on old history.** Stash on a commit far enough back that it's past the first page (2,000 commits, so use a big repo). Scroll down until more history loads: the stash's row appears with that page, near its commit. Until then, it's only in the rail's Stashes list. *Before:* such a stash never got a row, even after more history loaded.
6. Uncommitted-changes rows still stay at the very top; only stash rows moved.

## Feedback round 1: hiding branches

1. **Hide one.** Hover a branch in the rail's Local or Remotes list: an eye appears at the right. Click it: the branch leaves the graph (its pill, and any commits only it reaches), and its rail row stays, dimmed and italic with the eye struck through. The header shows "N · 1 hidden". Click the struck eye to bring it back. Or right-click a pill in the graph → **Hide <branch> from the graph** (the toast offers Undo). Branches a worktree has checked out, and the main line (`main` / `origin/main`), can't be hidden; they get no eye, and the pill menu says why.
2. **Show everything again.** The **⋯** on the Local or Remotes header → **Show all N hidden local/remote branches**.
3. **Auto-hide.** Remotes' **⋯** → **Hide new remote branches that aren't mine** (its checkbox is ticked when it's on). Turning it on hides nothing that's already there. Then make a remote branch that isn't yours appear: e.g. have someone push one, or run `git fetch` after Dependabot opens a PR. On the next refresh it's hidden, with a toast "Hid origin/… : a new branch that isn't yours" and Undo. A new remote branch with a commit of yours (one you pushed from another clone) stays visible. "Yours" = a commit that main doesn't have, made with your git `user.email` or `user.name`.
4. **Per repo, every worktree.** What's hidden is remembered per repository and is the same in every worktree of it, and after closing and reopening the window.

## CP12–CP14: drag to merge, rebase, cherry-pick and make worktrees

Use a throwaway clone. Set it up with: two local branches that have diverged (`a` and `b`, each with a commit the other lacks), a branch `behind` that is an ancestor of `main` (`git branch behind main~2`), and one extra worktree (`git worktree add ..\<repo>--try b`). *Before (all of these):* nothing in the graph or rail could be dragged.

**The gesture (CP12)**

1. **Start a drag.** Press on a branch pill in the graph (or a branch in the rail's Local/Remotes lists, or a worktree card) and move a few pixels. A small card follows the pointer with the branch name, and a hint line under it. Pressing on a commit row (not a pill) and moving drags the commit (the card shows its short hash and subject). Tags, stashes and WIP rows don't drag. A plain click still just selects/jumps as before.
2. **Targets light up.** Over a branch pill: that row gets an outline and the pill a ring, and the hint says what a drop would do ("Merge a into b in <worktree>", "· 1 more on drop" when the menu has more). Over a row but not on a pill, the row's local branch is the target. Over a worktree's WIP row, or a worktree card in the rail, the target is that worktree. Over nothing useful: "Drop on a branch, a worktree or + New worktree. Esc cancels."
3. **New worktree zone.** While dragging, a "+ New worktree" box appears under the worktree cards in the rail; it disappears when the drag ends.
4. **Auto-scroll.** Drag towards the top or bottom edge of the graph: it scrolls, and the target under the pointer updates.
5. **Cancel.** Esc during a drag, or releasing over nothing, ends it with no menu and no change.

**The drop menu and operations (CP13)**

Every menu item names what happens and where (the worktree), with the git command underneath in mono. A session working in the worktree an option runs in adds an italic warning line at the top (warning only). Every success shows the toast with **Undo**.

6. **Diverged branches.** Drag `a` onto `b`: **Merge a into b in <worktree that has b>** and **Rebase a onto b** (if no worktree has `a`, the rebase says "(checks out a in <this worktree> first)"). Pick Merge: `b` gets a merge commit in the worktree that has it (that can be the extra worktree; this window's worktree isn't touched). **Undo** resets `b` back (`reset --keep`, so it refuses rather than lose changes).
7. **Rebase.** Drag `a` onto `b` again and pick Rebase: `a` is replayed on `b`. Undo puts `a` back where it was, and switches this worktree back if the rebase had to check `a` out.
8. **Fast-forward.** Drag `main` onto `behind`: one option, **Fast-forward behind to main** (`git fetch . main:behind` when no worktree has `behind`, `git merge --ff-only` in its worktree when one does). Undo moves it back. Dragging `behind` onto `main` instead says "main already contains behind." in a toast, with no menu.
9. **Local onto remote.** Drag a local branch onto its `origin/...` pill: rebase onto it when they've diverged, fast-forward when the local one is just behind.
10. **Cherry-pick.** Drag a commit row from `a` onto the `b` pill: **Cherry-pick abc1234 onto b in <worktree>**. Dropping a commit onto a branch that already contains it says so.
11. **Switch first needs a clean tree.** An option that would check a branch out in this worktree first is greyed out ("· commit or stash this worktree's changes first") while this worktree has changes.
12. **Conflicts.** Make `a` and `b` change the same line, drag `a` onto `b` and Merge in this window's worktree: the toast says it stopped on conflicts, and an orange banner appears under the graph title: "A merge is in progress in <worktree>: N conflicted files. Resolve and stage them in Changes, then Continue." with **Continue** and **Abort** (and **Skip commit** for a rebase or cherry-pick). The conflicted files show as `U` in Changes. Abort puts it back; resolving, staging and Continue finishes it (no editor opens). If the conflict happened in *another* worktree, the toast instead offers **Open <worktree>**, which re-points the window there (where the banner then shows).

**Worktrees from drag (CP14)**

13. **Onto a worktree.** Drag a free branch onto the extra worktree's card: **Check out <branch> in <worktree>**; it switches that worktree, not this one. If that worktree has changes, you're asked stash / bring along / cancel first. Dragging a branch that another worktree holds offers only a detached checkout. Dragging a commit onto a card offers cherry-pick onto that worktree's branch and a detached checkout.
14. **New worktree.** Drag a branch no worktree has onto **+ New worktree**: **New worktree for <branch>**, command `git worktree add ..\<repo>--<branch> <branch>` (or, in a repo whose existing worktrees follow another layout, that layout). The toast says "Made worktree <folder> on <branch>" with **Undo** (removes the worktree) and **Start a session there** (opens a Perch session window in it). The new worktree appears in the rail.
15. **New worktree, new branch.** Drag a remote-only branch onto the zone: a tracking branch of the same name in a new worktree. Drag a branch another worktree holds, or a commit: the branch bar opens ("New worktree on a new branch from …"); type a name and Enter. Undo removes the worktree and deletes that new branch (only if it hasn't moved).
16. **Card menu.** Right-click a worktree card: **Open <name> in this window**, **Start a Claude session in <name>**, **Remove <name>…** (not for this window's worktree or the main one), **Prune worktrees whose folders are gone**. Remove on a clean worktree just goes; on one with changes, or with a session working in it, it asks first (and only then forces). The branch stays.

These have been verified headlessly: a synthetic pointer drag in `render` (`git_tree_drag_pill_1x.png`, `git_tree_drag_newworktree_1x.png`, `git_tree_drop_menu_1x.png`), the banner in `git_tree_checkout_1x.png`, and every git operation and its Undo by integration tests against a throwaway repo. Not on a real desktop: the feel of the drag, menu placement at the pointer, and anything multi-monitor.
