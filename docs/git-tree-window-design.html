The Tree.
A scoped git flow, built on what already ships.

A resizable window that focuses on this branch — from HEAD back to where it diverged from main — as a graph on the left, the files each node touched in the middle, the diff on the right, and a live working-tree node at the top where you author commits inline. It replaces Review changes, reusing that feature's plumbing almost wholesale. This is Perch stepping deliberately toward a lightweight git client.

Builds on M0 + M1 (shipped) Reuses DiffView, GitRepoService Replaces Review changes… Full-tree view = Phase 3 / later

The interactions

Five verbs

Each is a discrete action, not a step in a wizard — you drop into any of them at will. Only the last one waits for Phase 3.

Open

Right-click → View tree

The session flyout's Review changes… item becomes View tree… — the tree is a superset, so Review folds into the WIP node.

  • Right-click a session row on the overlay
  • MenuItem("View tree…"), gated by GitRepoService.IsRepo(cwd)
  • Fires ViewTreeRequested → WindowHost.ShowOrFocus → single reused TreeWindow
Inspect

Click a node → its files

Selecting a commit (or the WIP node) loads what it changed into the middle pane and clears the diff.

  • Commit node → GetCommitDiff(cwd, hash)
  • WIP node → GetStatus(cwd) → A / M / D list
  • Off-thread + generation token; middle pane repopulates
Diff

Click a file → the diff

Exactly the Review-changes experience, because it is literally the same control.

  • DiffView.SetSections(...) with the file's hunks
  • Unified / Split / Wrap / Ctrl-F all come free
  • WIP files that are staged and unstaged show two labelled sections
Commit

Author at the WIP node

Selecting the working-tree node opens an inline composer — tick files, write a message, commit. This is the unstarted M2, surfaced in the tree.

  • Per-file stage toggle → git add / restore --staged
  • Message box (StickyNote-style) → git commit
  • Active session → ConfirmDialog guard first
Expand · later

The full GitKraken tree

The toolbar button that unfolds every branch and remote into a lane-routed graph. Known destination, not first-pass work.

  • Owner-drawn lanes (the measure-or-paint / HighlightLayer pattern)
  • Merge routing, branch & remote heads, history search
  • Eventually: push. This is M3.

How it's built

Mostly assembly, not invention

The Session Change Review feature already gave us the read data layer, the diff surface, the reused-window idiom and the flyout entry point. Here's what each piece contributes and what's genuinely new.

PieceStatusWhat it does here
Right-click entry replace Rename the existing Review changes… flyout item to MenuItem("View tree…") and swap ReviewChangesRequested for ViewTreeRequested — same IsRepo gate, same ShowGitReview switch. The old GitReviewWindow retires once the WIP node covers it.
Window lifecycle reuse WindowHost.ShowOrFocus + a _treeWindow field nulled on close and torn down in CloseAuxWindows — identical to GitReviewWindow. New TreeWindow copies its async-load + generation-token + FileSystemWatcher scaffolding.
Diff surface reuse DiffView unchanged — bands, unified/split, wrap, find, selection, copy. It already accepts DiffSection[], which is exactly the shape a node produces.
Read data layer extend GitRepoService already has GetStatus, GetLog, GetCommitDiff, GetWorkingDiff. Add: %P parent hashes on GitCommit; a MergeBase(cwd, baseRef) call (git merge-base) so the log scopes to the divergence point; and remote/base-ref discovery (upstream → origin → local default) for the fork case.
Commit graph (left) new Phase 1: a plain ListBox of nodes with a one-lane CSS-style rail — cheap, glanceable. Phase 3: owner-drawn lanes behind the list via the StatsDashboard measure-or-paint routine and the DiffView.HighlightLayer "paint behind the rows" trick.
Commit authoring new The planned M2: git add / restore --staged / commit on GitRepoService (surfacing failures, unlike the read path), a StickyNote-style editor, and the ConfirmDialog guard when the session is Active.
Panel resizing new Swap the fixed Width = 320 columns for GridSplitters so graph / files / diff are user-adjustable. Small, self-contained.

Phasing

Three phases, mapped to the existing plan

These line up with the Session Change Review milestones already in docs/git-review-plan.md, so the tree is a continuation of that roadmap rather than a fork of it.

1≈ M1 done

Scoped branch tree — read-only

The window, the first-parent commit list, the WIP node, node → files → diff. Everything reuses shipped code; the only new pieces are the node list, the parent-hash log tweak, and the splitters.

  • New TreeWindow off the GitReviewWindow template; retires Review changes…
  • One-lane node list, WIP node at HEAD's tip, scoped to merge-base(HEAD, main)
  • Base-ref control + fork detection (upstream → origin)
  • %P parents on GitCommit; GridSplitter panels

Exit: usable for a week as a read-only branch inspector before any write path lands.

2= M2 next

Inline commit authoring at WIP

The working-tree node becomes interactive: stage per file, write a message, commit. This is the real M2 — the only difference is it's surfaced in the tree instead of a separate button.

  • Stage / unstage whole files → git add · git restore --staged
  • Composer → git commit, surfacing failures
  • Active-session guard via ConfirmDialog — refuse-or-confirm

Whole-file granularity only. Push and hunk/line staging stay out of scope for now.

3= M3 vision

Expand to the full tree

The GitKraken destination: every branch and remote in one lane-routed graph. Cuttable, expensive, and the reason the graph starts owner-drawable in Phase 1's structure.

  • Lane routing across merges, branch & remote heads
  • Owner-drawn lanes (measure-or-paint + paint-behind-rows)
  • Hunk / line-by-line staging in the diff pane
  • History search; eventually push

Now settled

Decisions

The four open questions, answered — plus the one detail that still needs designing.

decidedOne window

View tree replaces Review changes. The tree is a superset, so Review folds into the WIP node and GitReviewWindow retires.

decidedScope = the divergence

The graph runs from HEAD back to merge-base(HEAD, main) — where the branch left main. No arbitrary commit cap.

decidedToward a git client

The audit-vs-client hesitation is resolved: this is Perch becoming a lightweight git client, on purpose.

decidedWhole-file staging first

Phase 2 stages whole files. Hunk / line-by-line staging is a wanted future capability, deferred to Phase 3.

to designThe fork base-ref

Best practice is branch from origin and commit to a fork, so "main" may live on a different remote. The base-ref control needs a sane default — prefer an upstream remote's default branch, fall back to origin, then local main/master — with a manual override for the odd layout.
